# Changelog

All notable changes to this project are documented here.

## [Unreleased]

- **Token and password files saved with a byte order mark are read:** a file written by an editor of Windows as "UTF-8 with BOM" kept the mark in front of the secret, so the credential was refused or could not be sent in a header. The mark is dropped now; a file in another encoding (UTF-16) is refused with a clear message.
- **The steps of a reproduction and the shared CI validator run with the same limits as the complete mode, and the plan of the CI names the script it approves:** one runner (`procs.run_bounded`) puts the command in its own process group, stops it when its output passes the limit or its time is up and ends the processes it started, so a step that leaves a child behind no longer leaves it running; the plan of the shared CI validator now carries the SHA-256 of each `tools/ci_validate.py`, so a script changed after the approval is not run (this changes the digest of the plan: a plan approved before needs a new approval).
- **The shared CI validator runs with a short list of environment names instead of everything except what looks like a secret:** `plugin_ci` and the complete mode now build the environment of a repository's command with the same function (`procs.minimal_environment`: `PATH`, the system and user folders, the locale and the time zone, never a name that looks like a secret), so a variable of the person that has an innocent name no longer reaches the code of a repository.
- **The edges of the incoming evidence are hardened:** a signature that is not 64 lowercase hexadecimal digits (a non-ASCII text included) is refused as a wrong signature instead of raising, a `sent_at` that is not a finite number is refused as out of the age window, `NaN` and `Infinity` in a message file are rejected as invalid JSON, and a configuration whose `ingest.nonceRetentionSeconds` is shorter than twice `ingest.maxClockSkewSeconds` is refused with the value to raise it to, so that a message cannot be replayed after its nonce is forgotten.

## [0.0.4]

- **The SDK pin and the shared tools are up to date:** the SDK dependency names the newest release tag, and the shared tools are the canonical copies again.
- **Simulated message streams with injected faults, tests for the approval gate, the schema checker and every refusal of a signed message, and a coverage floor:** the `Simulation bench` workflow feeds the real ingest streams of signed messages from simulated technician nodes (replays, tampering, a wrong secret, clock skew, a wrong destination) from a fixed seed and checks that only the good, new ones are accepted and that a nonce is accepted once. New tests cover the approval gate (no terminal, wrong or empty confirmation, expiry, single use, binding to subject, action and digest), the small schema checker and each reason a message is refused. The coverage job measures statements and branches and fails under a floor that must not go down.
- **README: the platform statement:** a note says that where the README speaks of the CM5 it means the pilot bench that runs today, and that the target platform of HYDRA-UMC, an NVIDIA Jetson Orin NX 16 GB, is a design that has not been built or tested.
- **The evidence bundle is checked by the shared SDK:** the checksum and the shape of a bundle come from `hydra_umc_sdk.evidence_bundle` instead of a copy kept here, so the reader and the technician that writes the bundle cannot compute them differently. The SDK is the `sdk` extra (as for the repro verdict); without it a bundle is refused with a message that says so.
- **The contract of the evidence bundle is the one of the shared SDK:** `contracts/evidence_bundle.schema.json` is now the closed schema of the SDK (no field outside the contract), and a test compares it with the SDK checkout when one is at hand (`HYDRA_UMC_SDK_DIR` or a sibling folder), so the copy cannot drift.

- Build version synchronized with `hydra-umc.project.json` and the repository-native version source.

## [0.0.3] - panel push sends the status document to HYDRA-UMC-SERVER with the token of this node (serverPush, off by default): POST /api/ingest/developer-node/status with Authorization: Bearer <token> and X-Node-Id. HTTPS only (plain http... (and 1 more changes)

- **`panel push` sends the status document to HYDRA-UMC-SERVER with the token of this node (`serverPush`, off by default):** `POST /api/ingest/developer-node/status` with `Authorization: Bearer <token>` and `X-Node-Id`. HTTPS only (plain http for this machine alone), no redirect is followed, a token that is missing or too short sends nothing, and the token is never printed or put in an error. The token comes from an environment variable or a file, never from the configuration file. 8 tests.

- **The build test of the repository compiles only on CI or when allowed:** for the stacks that compile (`rust`, `go`, `android`, `flutter`, `firmware-c`), `tools/build_test.py` prints `BUILD_TEST=SKIPPED` with exit status 2 on a plain PC, never a pass; `ALLOW_LOCAL_BUILD=1` allows it and a CI runner always may. The `python` and `node` stacks are not locked.

## [0.0.2] - A full mode of the ecosystem CI plugin that runs the heavy tests of every repository after one approval of the whole batch, one repository at a time, with limits of time, output and free disk, and a consolidated report

- **Complete mode of the `ecosystem-ci` plugin, closed by default:** besides the shared CI, it can run the heavy test a repository declares in its manifest (`developer_node.full_test`); a repository that declares nothing runs nothing. The plan lists every command repository by repository with the SHA-256 of each script, and a person approves the whole batch by its digest (it expires and is used up by the run) after leaving out the repositories they do not want.
- **Serial and bounded runs:** one command at a time, a time limit per command and in total, a limit on the output size, a minimal environment without anything that looks like a secret, offline hints unless the repository declares that it needs the network and the configuration allows it, and nothing outside the approved list is ever started.
- **Disk protection:** the complete mode refuses to start, and stops between commands, when the disk of the workspace has less free space than `ecosystemCiFull.minFreeGb` (10 GB by default).
- **Clean cancellation and a consolidated report:** Ctrl+C ends only the processes the run started and still writes the report (`pass`, `fail`, `timeout`, `skipped` per command, with the duration and a short redacted tail); the exit code is not 0 when anything failed, timed out or was cut short.
- **New commands and settings:** `plugin full-plan`, `full-approve` and `full-run` (each with `--exclude`), the `ecosystemCiFull` section of the configuration file, the `ecosystem-ci-full-report/1` contract and `last_ci_full_report` in the status document, with the new texts in eight languages.

## [0.0.1] - The first pieces of the developer node: evidence intake, repro cases, a cache of checkouts, a status document and the ecosystem-ci plugin, all closed by default

- **Evidence intake, closed by default:** `evidence verify` checks a bundle of the local technician without storing it; `evidence ingest` also accepts a signed `incident-transport/1` message (HMAC-SHA256, receiver, age, nonce kept against replay) and stores a verified bundle as a case that waits for a person. A bundle that was edited after assembly or that carries a secret shape is refused; nothing in it is ever run.
- **Executable repro cases, closed by default:** a recipe (a list of argument lists and one condition) runs only when the part is on, every program is in the allow-list of the configuration and a person approved its exact digest at a terminal (expiring, single use). Each run is a `ScenarioOutcome` of the SDK contract; the verdict of a before and after pair is computed by the SDK (optional `sdk` extra, pinned to a tag).
- **Checkout cache by revision, closed by default:** a bare mirror per allowed remote and one detached git worktree per commit, a pinned commit is verified, and the cache keeps to a limit in GB set in the configuration by removing the least recently used worktrees.
- **Status document for dashboards and studios:** `developer-node-status/1` with the switches, the queue, the journal and the health, in eight languages, written to a file (no port, no command channel).
- **`ecosystem-ci` plugin, closed by default:** the shared CI validator of each repository of a workspace, one after another, after a person approved the exact plan, with one consolidated report.
- One JSON configuration file for every switch and every tuned value; texts of the command line and the panel in eight languages.
